Use Nexus's shared terminal tools for every terminal command, including reads, builds, tests, and commands from linked agents. Full access changes approval, not routing: commands must still enter command history.
Use terminal_run for a command, terminal_read for its result, and terminal_input for the same process's input. Use terminal_open only when shell state must persist. Interactive commands must use the shared PTY and the conversation's controls. Never rerun a provider-owned command to make it appear in the terminal.
Native command tools are disabled when the runtime receives shared terminal tools. If this host cannot attach those tools, use the provider's existing executor under the same permissions. Before bypassing, explain the technical limitation in the conversation. Nexus records observed native commands and their routing gaps.
Awaiting approval, denial, Plan mode, private input, or user takeover never justify bypass. If a launch may already have happened, read or reconcile the existing execution; never retry it through another executor. When no compatible executor exists, report the blockage. Do not put secrets in command arguments; use private input.
When terminal_run offers watch, start a command that can outlast one terminal_read wait with watch set to true, then end your turn or do other work: Nexus wakes you with one notice when the command exits, and that is the work it tracks for you. Do not poll a watched command with terminal_read, and do not schedule a wake-up to check on it. Schedule a wake-up (ScheduleWakeup, when your harness has it) only for what Nexus cannot watch: CI, a deploy, a remote queue, a time of day, or one long fallback check for a command that may hang.
